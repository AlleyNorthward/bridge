# datastructure —— 小型 OJ

本仓库是一个小型算法 OJ。用户给出题目后，按本文档的固定流程产出整套题包，不用每次重复说明。

## 目录约定

每道题一个目录，结构固定：

```text
algorithm/<章节目录>/<序号_题目名>/
├── problem.md            # OJ 格式题面
├── answer.md             # 空占位文件（不写任何答案）
├── test/
│   ├── 01.in ... 20.in   # 20 组输入，补零两位
│   └── 01.out ... 20.out # 对应输出，补零两位
└── solutions/
    ├── main.c
    ├── main.cpp
    ├── main.java
    ├── main.lua
    ├── main.py
    └── main.ts
```

- 题目的章节、序号、题目名和**目标文件夹由用户指定**，不要自己编；用户只给题目信息、没说放哪时先问。
- 参考实例：`algorithm/顺序表/01_翻转/01_基础翻转/`。
- 测试文件命名**补零两位**：`01.in` … `20.in`，保证按文件名排序即按序号排序。
- 换行沿用现有文件：**CRLF**；编码 UTF-8。
- `solutions/` 下六个文件是**空占位文件**（只建文件、不写代码），由用户自己完成。
- `answer.md` 是**空占位文件**，不写题解或思路。
- 六种语言固定为：C、C++、Java、Lua、Python、TypeScript。

## 红线：不提供任何答案

- 绝不写解法代码、不往 `answer.md` 填内容、聊天回复里也不贴解法或思路答案。
- `.out` 的正确性由临时脚本保证：**Python + C 对拍**（不用 C++）。
- 参考实现放仓库外临时目录，用完连同编译产物（`.o` / `.exe` / 可执行文件）一起删除。

## problem.md 格式

严格沿用现有题面的结构与风格：

````markdown
## id
<数字编号，取自 algorithm/id.md 的最大 id + 1>

## 问题
# <题目名>

## 题目描述

...

## 输入格式

...

## 输出格式

...

## 数据范围

- ...

## 输入输出示例

### 示例 1

输入:

```text
...
```

输出:

```text
...
```

### 示例 2

...

## 要求

- 时间复杂度:\(O(n)\)
- 辅助空间复杂度:\(O(1)\)

## AC次数

0
````

要求：

- 题面用中文；数学符号用 LaTeX 的 `\( ... \)`，与现有题面一致。
- 至少给 2 组示例，且示例必须真实存在于 `test/` 中（通常就是 `01.in` / `01.out`）。
- 输入/输出格式写清楚：例如"第一行 n，第二行 n 个整数，空格分隔"。
- 数据范围要具体（n 的上界、元素值域等）。

## 题目 ID 与本地测试

- 每题一个唯一 id：**纯数字**，从 1 开始递增。`algorithm/id.md` 是全局 id 登记表，格式：

        | id | 题目路径 |
        | --- | --- |
        | 1 | algorithm/顺序表/01_翻转/01_基础翻转 |

  新题取表中**最大 id + 1**（删除题目也不回收 id），建好题包后在 `id.md` 追加一行。
  id 写在 `problem.md` 第一段，例如：

        ## id
        1

        ## 问题
        # 题目名

- 本地测试用 pwsh 模块 `Ninth_Module_Test.psm1` 提供的 `ioj` 命令（模块路径：
  `F:\0github\Learning-Computers\computer\terminal\powershell\powershell-module\Ninth_Module_Test.psm1`）。
  模块由 pwsh 启动时自动加载，**不需要每次运行脚本，也不需要在仓库里放任何包装脚本**：

        ioj <id> <language>

  `language`：`c`、`cpp`、`java`、`lua`、`python`、`typescript`（或 `ts`）。

  模块会：按 id 在所有 `problem.md` 中定位题目目录 → 直接用编译器命令行参数编译 → 在对应目录执行
  `oj test -d <题目>/test -c <命令> -N`。编译产物统一放 `build/<id>/`。**全部 AC 时**自动把该题
  `problem.md` 的 `## AC次数` 加 1（不分语言，一次完整通过只记一次）。

- 仓库**不依赖**根目录的 `main.*`、`makefile`、`include/`、`dist/`、`tsconfig.json`、`package.json`；
  除题目、测试、`algorithm/id.md`、`CLAUDE.md` 和 `.gitignore` 外不需要额外文件。

- TypeScript 由 `tsc` 命令行参数直接编译到 `build/<id>/ts/`，不需要 `tsconfig.json`。
  Java 的入口类名必须是 `main`（与 `main.java` 同名）。

## 测试数据规范

共 **20** 组，`01.in..20.in` 与 `01.out..20.out` 一一对应。第 1 组通常就是题面示例。

核心原则：**每组数据都要有意义、有区分度**，不能凑数。

- **随机性强**：数值在全值域随机；分布要多样（纯随机、近似有序、锯齿、重复但非全同、正负混合、极端值混合等）。禁止大面积常数堆砌（例如大数据全是 `-5`、全是 `0`）。
- **规模灵活**：整体可在 `10^4 ~ 10^6` 之间选择，常规以 `10^5` 左右为宜；不要机械使用 `10^4` / `10^5` 这类整齐数字，用 `7919`、`12345`、`53433`、`77777` 等不规则规模拉开层次。题面上限只是上限，不是每组的默认值。
- **边界灵活**：`n=1`、`n=2`、`±10^9` 极值、重复元素等按题目真实边界设计；"全部相同 / 全负数"这类用例放小规模即可，不要用它填大数据的坑。
- **禁止零数据 / 空数据**：不使用 `n=0`（或等价的无元素输入）的用例，任何 `.in` / `.out` 都不允许是空文件；边界从 `n=1` 起步。
- **按算法特性定规模**：
  - 递归类实现注意栈深度，别用无意义的大规模数据把对拍/作答直接爆栈；
  - 最优解复杂度偏高（如 `O(n^2)`）的题目，规模相应下调，不要硬套 `10^5`；
  - 复杂度允许时可以上探到 `10^6`，但仍以能区分算法表现为准。
- 输出：元素间单个空格，行末换行；判题按 **token 比较**（忽略多余空白），所以换行位置不敏感，但不要输出多余 token。
- 不允许出现空文件：每个 `.in` 至少有一个 token，每个 `.out` 至少有一个 token。

## 出题流程（收到题目后执行）

1. 复述题目与输入输出格式；有歧义先问，不要猜。
2. 使用用户指定的目标文件夹；用户没给就问。
3. 读取 `algorithm/id.md`，取最大 id + 1 作为新题 id；写 `problem.md`（首段 `## id`，其次 `## 问题`，文末 `## AC次数` 初始为 `0`），创建空的 `answer.md`，并在 `id.md` 追加登记。
4. 写参考实现做正确性保证：**一份 Python + 一份 C**（不用 C++）。两份都放仓库外的临时目录，不留在题包里。
5. 生成 20 组输入；Python 与 C 两份实现分别计算，结果不一致就排查（通常是题面歧义或边界处理），一致后再落盘 `.out`。
6. 建 `solutions/` 六个空文件（不写任何代码）。
7. **清理临时文件**：删除参考实现源码、C 编译产物（`.o` / `.exe`）以及整个临时目录，确认仓库里没有残留。
8. 自检：`problem.md` 的 `## id` 为数字且全局唯一、在 `algorithm/id.md` 有登记；`## AC次数` 存在且为 `0`；20 个 `01.in..20.in` 与 `01.out..20.out` 一一对应、无缺失；题面示例与 `test/01` 一致；`answer.md` 与六个 solution 文件均为空。
9. 汇报：题目路径、测试规模概览、对拍是否通过。**不汇报解法内容。**

## 其他约定

- 不要修改已有题包，除非用户要求。
- `ioj` 的编译产物只写 `build/<id>/`，不要手动改。不主动 commit / push，除非用户明确要求。
- `question/` 是用户的学习笔记，和 OJ 题包无关，不要套用题包格式。
